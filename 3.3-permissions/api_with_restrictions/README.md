# API объявлений

Учебный backend для приложения с объявлениями на Django REST Framework.

Объявления доступны для просмотра без авторизации. Для создания,
изменения и удаления используется токен-аутентификация.

## Возможности

- Просмотр списка и отдельного объявления без авторизации.
- Создание объявлений авторизованными пользователями.
- Изменение и удаление объявления только его автором.
- Статусы OPEN и CLOSED.
- Ограничение: не более 10 открытых объявлений у одного пользователя.
- Проверка лимита при создании и изменении статуса объявления.
- Фильтрация по автору, статусу и диапазону дат создания.
- Ограничение частоты запросов:
  - анонимные пользователи — 10 запросов в минуту;
  - авторизованные пользователи — 20 запросов в минуту.

Дополнительные возможности из задания — избранное, статус DRAFT
и расширенные права администраторов — не реализованы.

## Локальный запуск

Команды ниже приведены для macOS/Linux.

### 1. Клонирование

```bash
git clone --branch video [https://github.com/anastasyatemirbulatova-cmd/dj-homeworks.git](https://github.com/anastasyatemirbulatova-cmd/dj-homeworks.git)
cd dj-homeworks/3.3-permissions/api_with_restrictions
```

### 2. Виртуальное окружение и зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### 3. PostgreSQL

Запустите сервер PostgreSQL.

Создайте базу netology_classified_ads через pgAdmin или SQL,
выполнив команду от пользователя с правом создания баз:

```sql
CREATE DATABASE netology_classified_ads;
```

Если база уже существует, повторно создавать её не нужно.

### 4. Переменные окружения

```bash
cp .env.example .env
```

Сгенерируйте ключ Django:

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Заполните локальный .env:

| Переменная | Назначение |
|---|---|
| DJANGO_SECRET_KEY | Секретный ключ Django |
| DJANGO_DEBUG | Режим отладки: True для локальной разработки |
| DJANGO_ALLOWED_HOSTS | Разрешённые имена хостов через запятую |
| DB_NAME | Название базы |
| DB_USER | Пользователь PostgreSQL |
| DB_PASSWORD | Пароль PostgreSQL |
| DB_HOST | Адрес PostgreSQL |
| DB_PORT | Порт PostgreSQL |

Файл .env не должен попадать в Git.
Для production используйте отдельные секреты и DEBUG=False.

Переменные, уже заданные в окружении процесса, имеют приоритет
над значениями из .env.

### 5. Миграции и администратор

```bash
python manage.py check
python manage.py migrate
python manage.py createsuperuser
```

### 6. Запуск

```bash
python manage.py runserver
```

Адреса:

- API: http://127.0.0.1:8000/api/advertisements/
- Админка: http://127.0.0.1:8000/admin/

## Аутентификация

1. Войдите в админку.
2. Создайте пользователей.
3. В разделе токенов создайте токен для каждого пользователя.
4. Передавайте токен в заголовке:

```http
Authorization: Token YOUR_TOKEN
```

Не публикуйте настоящие токены в репозитории.

Вход в админку не заменяет передачу токена при запросах к API.

## Маршруты API

| Метод | Маршрут | Назначение | Доступ |
|---|---|---|---|
| GET | /api/advertisements/ | Список объявлений | Всем |
| POST | /api/advertisements/ | Создание | Авторизованным |
| GET | /api/advertisements/{id}/ | Просмотр объявления | Всем |
| PUT | /api/advertisements/{id}/ | Полное обновление | Автору |
| PATCH | /api/advertisements/{id}/ | Частичное обновление | Автору |
| DELETE | /api/advertisements/{id}/ | Удаление | Автору |

Создатель назначается сервером из текущего пользователя.
Передать или изменить автора через поле creator нельзя.

В обязательной реализации суперпользователь не получает права
изменять чужие объявления через API.

## Фильтрация

По статусу:

```text
/api/advertisements/?status=OPEN
```

По автору:

```text
/api/advertisements/?creator=1
```

По диапазону дат создания:

```text
/api/advertisements/?created_at_after=2026-10-01&created_at_before=2026-10-27
```

Можно использовать только одну границу даты.
Фильтры можно комбинировать.

## Проверка API

Примеры запросов находятся в requests-examples.http.
Замените заглушки токенов локально и не коммитьте реальные ключи.

В ходе ручной проверки подтверждены:

- просмотр без авторизации;
- запрет создания без токена;
- создание с токеном;
- запрет изменения и удаления чужого объявления;
- изменение и удаление своего объявления;
- ограничение в 10 открытых объявлений;
- редактирование при достигнутом лимите;
- создание закрытого объявления при достигнутом лимите;
- запрет перехода CLOSED → OPEN при достигнутом лимите;
- фильтрация по статусу и дате;
- лимиты 10 и 20 запросов в минуту.

Ожидаемые коды ответов:

| Код | Значение |
|---|---|
| 200 | Успешный просмотр или изменение |
| 201 | Объявление создано |
| 204 | Объявление удалено |
| 400 | Ошибка валидации |
| 401 | Нет действительных учётных данных |
| 403 | Нет прав на действие |
| 404 | Объект не найден |
| 429 | Превышен лимит запросов |

Автоматические тесты в текущую версию не включены.

## Ограничения

Проект предназначен для учебного локального запуска.

- Лимит открытых объявлений проверяется в сериализаторе.
  Строгая защита от одновременного создания объявлений
  несколькими запросами не реализована.
- Встроенный throttling DRF не заменяет защиту инфраструктуры от DDoS.
- Для production необходимы отдельная настройка сервера,
  HTTPS, секретов, логирования и кэша.

Если браузер блокирует адрес advertisements, отключите блокировщик
рекламы для локального сайта или проверяйте API через HTTP-клиент.
